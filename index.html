¿Qué es la Vulnerabilidad de Race Condition en la Actualización de WordPress y RCE?

      

        
La condición de carrera durante la actualización de WordPress se presenta cuando el gestor de paquetes descarga y descomprime archivos ZIP directamente en wp-content/upgrade/, ubicado dentro de la raíz web pública del servidor. Durante ese intervalo, mientras se extraen los archivos y antes de que se completen las verificaciones o el descarte de temporales, los archivos PHP resultan accesibles transitoriamente mediante peticiones HTTP directas.

        
En servidores con configuraciones habituales de Nginx o Apache que carecen de directivas explícitas contra la ejecución de scripts interpretados en carpetas de contenido, un atacante que dispare peticiones masivas concurrentes puede activar estos archivos recién extraídos. Este vector deriva en Ejecución Remota de Código (RCE) con los privilegios del proceso web (como www-data), comprometiendo por completo la aplicación.

        
La mitigación corporativa exige tres capas coordinadas de defensa en profundidad: reubicar WP_TEMP_DIR en wp-config.php hacia un directorio fuera de la raíz web con permisos restringidos, bloquear categóricamente en el servidor web la compilación de PHP en uploads y upgrade, y activar reglas perimetrales en Cloudflare WAF para neutralizar cualquier intento malicioso en el borde perimetral global.

Preguntas Frecuentes sobre Seguridad en Actualizaciones de WordPress

      

        

          
          

            Durante la actualización de core, temas o plugins, WordPress descarga un paquete ZIP y lo descomprime temporalmente en wp-content/upgrade/. Si el servidor permite ejecución de PHP en esa carpeta, existe una ventana de concurrencia donde un atacante puede solicitar los archivos recién extraídos antes de que WordPress concluya la validación y limpieza, logrando ejecución remota de código.
          

        

        

          
          

            La carpeta de upgrade tiene como única función la extracción transitoria de archivos. Ningún script PHP en wp-content/upgrade/ debe ser invocado directamente vía web. Bloquear la ejecución impide que eventuales condiciones de carrera o archivos huérfanos se transformen en web shells activas.
          

        

        

          
          

            La constante WP_TEMP_DIR configurada en wp-config.php define una ruta del sistema operativo fuera de la raíz pública web (como /var/www/tmp/). Al trasladar los archivos temporales fuera del DocumentRoot, resulta físicamente imposible para un atacante alcanzarlos o ejecutarlos vía peticiones HTTP.
          

        

        

          
          

            Sí. Una regla personalizada de WAF en Cloudflare bloqueando cualquier petición donde la ruta contenga wp-content/upgrade/ intercepta y descarta intentos de explotación en el borde perimetral global antes de que lleguen al servidor de origen.
          

        

        

          
          

            Los navegadores web imponen restricciones de seguridad sandbox (Same-Origin Policy y CORS) que impiden inspeccionar cabeceras profundas y códigos HTTP reales en dominios de terceros. El script Python opera directamente sobre sockets de red, garantizando diagnósticos determinísticos y fiables.
