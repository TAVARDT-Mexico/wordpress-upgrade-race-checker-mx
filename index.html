Definición Técnica y Mecánica de Ataque

¿Qué es la Vulnerabilidad de Race Condition en la Actualización de WordPress y RCE?

La vulnerabilidad de Race Condition en la Actualización de WordPress ocurre durante el proceso de actualización de componentes gestionado por class-wp-upgrader.php. WordPress descarga el archivo comprimido en wp-content/upgrade/ y ejecuta unzip_file().

Durante la descompresión en disco y antes del traslado atómico final, los archivos PHP residen en la raíz web pública. Si el servidor (Nginx o Apache) no cuenta con bloqueo perimetral y PHP-FPM compila scripts en esa carpeta, un atacante puede invocar los archivos mediante solicitudes concurrentes masivas, logrando Ejecución Remota de Código (RCE).

  • ✖ Carpeta wp-content/upgrade/ accesible directamente mediante HTTP.

  • ✖ Constante WP_TEMP_DIR no configurada, manteniendo temporales en raíz web.
  • ✖ Sin reglas perimetrales en WAF de borde para descartar peticiones maliciosas.
Servidor Blindado (TAVARDT Zero Trust)
  • ✔ Regla en Nginx / Apache bloqueando wp-content/upgrade/ con 403 Forbidden.
  • ✔ Listado de directorios desactivado terminantemente (Options -Indexes).
  • ✔ Directiva FastCGI prohibiendo compilación de PHP en rutas estáticas.
  • ✔ WP_TEMP_DIR aislado fuera de DocumentRoot (/var/www/tmp/) con permisos 0750.
  • ✔ Cloudflare WAF bloqueando de inmediato peticiones hacia carpetas de actualización.

Preguntas Frecuentes sobre Seguridad de Actualizaciones en WordPress

Al actualizar un complemento, WordPress descomprime el paquete ZIP en /wp-content/upgrade/. En la pequeña ventana de tiempo previa a la verificación e instalación definitiva, una solicitud concurrente puede invocar un script PHP recién extraído si el servidor permite su compilación.

Los directorios de contenido y actualización jamás deben procesar código PHP. Restringir la ejecución en estas rutas anula cualquier intento de ejecución de web shells o scripts maliciosos durante procesos transitorios.

La directiva WP_TEMP_DIR en wp-config.php define la ubicación donde WordPress almacena archivos temporales. Al asignarla fuera de la raíz web DocumentRoot, los clientes externos no pueden alcanzar los archivos vía HTTP.

Sí. Una regla personalizada en Cloudflare WAF que bloquee peticiones cuyo path contenga /wp-content/upgrade/ frena el ataque en el borde de la red antes de que alcance el servidor de origen.
